# notebooks-result-explanation/

Written documentation for the pipeline: the locked protocol, and one walkthrough per notebook.

| File | Covers |
|---|---|
| [`FINAL_PROTOCOL.md`](FINAL_PROTOCOL.md) | **The frozen evaluation protocol** — pre-registered rules and the response to each review round |
| [`ENHANCED_NOTEBOOK.md`](ENHANCED_NOTEBOOK.md) | The **final run**: its four protocol changes, why the decision order matters, the results self-audit, outputs, limitations |
| [`SIMPLE_NOTEBOOK.md`](SIMPLE_NOTEBOOK.md) | The earlier notebook: configuration, resume behaviour, artifacts, gates, verification |
| [`comparison.md`](comparison.md) | How the notebooks differ |
| [`resource.md`](resource.md) | Runtime and resource requirements per GPU |
| [`documentation.md`](documentation.md) | Method background and implementation notes |
| [`results.md`](results.md) | Results write-up and research-validity assessment |

> **On internal cross-references.** These documents were written alongside the experiments and
> sometimes cite paths from an earlier repository layout (`docs/…`, `experiment-result/…`). The
> content is unchanged and remains accurate; only the paths are historical. They are left as
> written rather than edited, because a protocol document that is quietly revised after the fact
> is worth less than one that is not.

Start with `FINAL_PROTOCOL.md` if you want to know what was promised, and `ENHANCED_NOTEBOOK.md`
if you want to know what was run.
